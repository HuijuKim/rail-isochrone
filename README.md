# 철도 등시선 (Rail Isochrone)

출발지와 출발 시각을 주면, 그 시각에 출발해 **전철 + 도보만으로** n분 안에
갈 수 있는 범위를 지도 위에 그린다.

경로 API를 호출해 격자를 샘플링하는 방식이 아니라, 시각표 전체를 로컬에
올려두고 다대다 도달시간을 직접 계산한다. 호출 제한이 없고 한 번 계산에
역 전부의 도착 시각이 한꺼번에 나온다.

## 빠른 시작

```
python src/fetch_data.py     # 시각표 원본 수집 (약 111 MB, 최초 1회)
python src/build_graph.py    # 라우팅용 배열로 변환 (약 40초)
python src/build_walk.py     # 보행 네트워크 구축 (선택, 아래 참고)
python src/server.py         # http://127.0.0.1:5173
```

데이터는 `data/regions/<권역>/` 아래에 모인다. 저장소에는 코드만 들어 있고
데이터는 위 순서대로 돌리면 그대로 만들어진다 (약 680 MB).

필요한 패키지: `numpy`, `scipy`, `matplotlib`, `flask` (+ 보행망을 쓰면 `osmium`)

### 테스트

```
python -m pytest tests/ -q      # 3초
```

상수를 만졌을 때 무엇이 움직이는지 보려고 기준선을 박아둔 회귀 테스트다.
값이 달라지면 고장이 아니라 "의도한 변화인지" 확인하고 기준선을 갱신하면 된다.
`tests/test_regression.py` 상단에 그 취지를 적어뒀다.

### 보행 네트워크 (선택)

`build_walk.py` 를 돌리지 않아도 앱은 동작한다. 그때 도보는 직선거리에 1.3배
우회 보정을 한 근사다. 실제 보행로를 따르게 하려면 OSM 추출본을 받아서
한 번 빌드하면 된다.

추출본이 둘인 이유가 있다. 야마나시와 이즈 반도는 Geofabrik 이 주부로
분류해서 간토 추출본에 없다. 그런데 주오선(고후까지), 후지큐, 이즈큐,
이즈하코네, 고텐바선은 시각표가 이미 있어 열차로는 닿는다. 보행망만 빠지면
그 역들이 "지원 역" 에서 빠지고 경계 밖으로 나간다.

```
curl -L -o data/osm/kanto-latest.osm.pbf  https://download.geofabrik.de/asia/japan/kanto-latest.osm.pbf  # 483 MB
curl -L -o data/osm/chubu-latest.osm.pbf  https://download.geofabrik.de/asia/japan/chubu-latest.osm.pbf  # 486 MB
python -m pip install osmium
python src/build_walk.py                                          # 10분 안팎
python src/build_admin.py                                         # 역마다 도도부현 붙이기, 1분
```

읽을 추출본은 `data/regions/<권역>/region.json` 의 `osm_files` 에 적는다.
격자 밖의 점은 읽으면서 버리므로 주부 추출본의 나고야는 들어오지 않는다.

**서버를 멈춘 뒤에 돌려야 한다.** 서버는 원본 기하 파일을 mmap 으로 열어 두는데
윈도우에서는 그게 파일 잠금이라 덮어쓰기가 막힌다. 빌드 시작 시점에 검사해서
막혀 있으면 바로 멈추고 알려준다.

`data/regions/<권역>/walk/` 가 생기면 서버가 자동으로 그쪽을 쓴다. 지우면
다시 직선거리 근사로 돌아간다.

### 지도 바꾸기 (선택)

기본은 OpenStreetMap이라 키 없이 바로 뜬다. 구글 지도를 쓰려면 Maps
JavaScript API 키를 넣으면 된다. 둘 중 아무 쪽이나.

```
set GOOGLE_MAPS_API_KEY=AIza...        # 환경변수
```

```json
// config.json  (프로젝트 루트)
{ "google_maps_api_key": "AIza..." }
```

키가 있으면 구글 지도로, 없거나 불러오기에 실패하면 OpenStreetMap으로
자동으로 돌아간다. 일본은 한국과 달리 지도 데이터 반출 제한이 없어서
구글 지도가 정상 동작한다.

과금은 Dynamic Maps SKU에 걸린다. 월 1만 회까지 무료, 넘으면 1,000회당
$7이다. 이 앱은 화면을 한 번 띄울 때 1회를 쓰므로 혼자 쓰는 수준에서는
무료 한도 안에서 끝난다.

## 계산 방식

### 1. 직통운전 병합 (`build_graph.py`)

수도권은 직통운전이 일상이라 (한조몬선 열차가 그대로 도부선으로, 도큐선에서
그대로 들어오는 식) 이걸 별개 열차로 두면 타고 가만히 있는 승객에게 환승
패널티가 잘못 붙는다. 데이터의 `nt`(next train) 체인을 따라가 하나의 연속
운행으로 잇는다. 48,709편이 34,243편으로 줄어든다.

### 2. 도달시간 계산 (`router.py`)

RAPTOR를 numpy로 벡터화했다. 한 라운드마다 63만 개 정차 이벤트를 한 번씩
훑으며 (a) 현재 라벨로 탈 수 있는 열차를 찾고 (b) 그 열차의 이후 정차역
도착 시각을 갱신한다. 더 나아지는 역이 없을 때까지 반복하므로 환승 횟수에
제한이 없다.

"같은 운행 안에서 이 정차 이전에 이미 탔는가"는 승차 가능 지점의 인덱스를
`np.maximum.accumulate`로 흘려보낸 뒤 운행 시작 인덱스와 비교해 구한다.
루프 없이 전체 이벤트를 한 번에 처리한다.

역 2,610행 전체 계산에 **0.07초**.

### 3. 보행 네트워크 (`build_walk.py`, `walknet.py`)

도보를 원으로 근사하면 강이나 선로처럼 못 건너는 곳을 그냥 가로지른다. 실제
보행로를 쓰려면 질의마다 수백만 노드 위에서 다익스트라를 돌려야 하는데 그러면
10초가 넘는다.

여기서 쓰는 성질은 **보행망이 출발 시각에 의존하지 않는다**는 것이다. 열차
시각표와 달리 도로는 언제 가든 같다. 그래서 역별 도보권을 한 번만 계산해
저장해두고, 질의할 때는 도달한 역들의 도보권을 겹쳐 최솟값만 취한다.

- OSM way 의 점들을 40 m 격자 셀로 스냅해 노드를 합친다. 원본 노드(1,581만 개)를
  그대로 쓰면 감당이 안 되는데, 40 m 로 묶으면 477만 개로 떨어진다. 100 m 로
  묶으면 더 가볍지만 폭 20-40 m 짜리 철도 부지나 좁은 하천의 양안 도로가 같은
  노드로 합쳐져 있지도 않은 건널목이 생긴다.
- 계산은 40 m 그래프에서 하되 **결과는 100 m 격자로 내려 담는다.** 정확도는
  촘촘한 쪽에서 얻고, 용량과 질의 속도는 성긴 쪽에서 얻는다.
- 간선 비용은 원본 점이 아니라 **셀 중심 사이 거리**로 잰다. 점 좌표를 쓰면
  셀 경계를 사이에 두고 몇 m 떨어진 두 점이 실제로는 100 m 떨어진 두 셀을 잇는
  간선을 헐값에 깔아서, 그런 간선이 연쇄되면 격자를 거의 공짜로 가로지른다.
- 계단(`highway=steps`)은 같은 거리라도 2.2배 시간이 든다.
- **주변과 끊긴 파편은 걷어낸다.** OSM 에는 도로망과 이어지지 않은 짧은 통로가
  곳곳에 있다. 역을 가장 가까운 노드에 그냥 붙이면 이런 파편에 걸리는 경우가
  생기고, 그러면 도보권이 한 칸뿐이라 도달 가능한데도 지도에 아무것도 그려지지
  않는다. 오후나나 공항제2빌딩 같은 큰 역도 걸렸다. 연결 성분이 50노드 미만이면
  버린다.
- 거리 배열을 역들 사이에 재사용하고 방문한 자리만 되돌리므로, 노드가 476만
  개여도 역 하나당 비용이 실제 도보권 크기에만 비례한다. 2,496개 역 전체가
  45초에 끝난다.

출발지와 도착지는 미리 알 수 없으므로 그때그때 국소 다익스트라를 돌린다.
반경이 작아 수십 ms 로 끝난다.

### 4. 경로 복원 (`router.py`)

도착 시각만 계산하면 "어떻게 도달했는지" 는 버려진다. 경로를 보여주려면 역마다
어느 열차를 어디서 탔는지도 남겨야 하는데, 그러면 라운드마다 최솟값만 취하는
대신 역별로 가장 빠른 후보와 그 출처를 함께 골라야 한다 (`_best_per_group`).

등시선에는 필요 없는 비용이라 `trace=True` 일 때만 켠다. 켜도 도착 시각은
같아야 하고, 그걸 테스트로 고정해 뒀다.

되짚기는 반드시 끝난다. 환승 비용과 승차 시간이 모두 양수라 구간마다 도착
시각이 엄격히 줄어들기 때문이다.

### 5. 등시선 렌더링 (`isochrone.py`)

역별 도보권을 도착 시각만큼 밀어 올려 겹치면, 격자 위에 "출발지에서 이
지점까지의 총 소요시간"이 그려진다. 등고선을 따면 그게 곧 등시선이다.

보행망 노드가 놓인 칸만 값을 갖기 때문에 그대로 등고선을 따면 건물 안쪽이
전부 구멍이 된다. 도로에서 200 m 안은 걸어 들어갈 수 있다고 보고 메운다.

matplotlib으로 등고선을 뽑고, 고리들의 포함 관계를 검사해 외곽선과 구멍으로
분류한 뒤 GeoJSON MultiPolygon으로 내보낸다.

## 권역 범위

앱이 동작하는 범위는 데이터에서 직접 뽑는다. 행정구역 경계는 쓸 수 없다.
도쿄도가 오가사와라까지 포함해서 간토 추출본 폴리곤이 태평양을 통째로
감싸기 때문이다.

- 역마다 **옆 역까지의 절반**을 반경으로 잡는다. 도심은 작게, 외곽은 크게
  잡히고 다음 역이 있는 방향으로는 그 중간에서 끊긴다.
- **종점은 다르다.** 바깥에 다음 역이 없으니 자를 이유가 없어 10 km 로
  넉넉히 잡는다. 안 그러면 미사키구치 너머 미우라 시가지처럼 "들어갈 수
  있는 지도가 없는" 곳이 생긴다.
- OSM 해안선으로 구운 육지 마스크(250 m)로 깎는다. 바다에 막혀 끝나는
  육지 조각은 통째로 넣는다.
- 판정과 지도에 그리는 선이 **같은 마스크**를 쓴다. 둘이 갈리면 선 밖인데
  클릭은 되는 상태가 된다.

## 화면에서 할 수 있는 것

- **출발지**: 역 이름으로 검색하거나 지도를 직접 누른다. 일본어·영어·한국어
  모두 검색된다.
- **도착지** (선택): 지정하면 거기까지의 **경로**를 노선별로 보여준다. 어느
  열차를 몇 시에 타서 어디서 갈아타는지, 내려서 몇 분 걷는지까지 나오고
  지도에는 실제 노선색으로 선이 그려진다. 전철보다 그냥 걷는 편이 빠르면
  그렇다고 말한다.
- 지도 클릭이 어느 쪽을 찍을지는 **입력칸을 누르면** 그쪽으로 넘어간다.
  지금 대상인 칸에 "지도 클릭" 표시가 붙는다.
- **지금** 버튼을 누르면 현재 시각으로 맞춰진다. 주말이면 다이어도 함께 바뀐다.
- 지도 **좌클릭은 출발지, 우클릭은 도착지**다. 입력칸을 누르면 좌클릭 대상이
  그쪽으로 바뀐다.
- **전철 없이 도보만** 을 켜면 대중교통을 빼고 걷기만 계산한다.
- 도보 시간은 두 겹이다. "하차 후 도보" 는 역에서 얼마나 걸을지, 접이식으로
  숨겨둔 "전체 도보" 는 여정 전체에서 걷는 시간의 상한이다.
- **현위치에서 출발**을 누르면 브라우저 위치로 출발지를 잡는다. 권역 밖이면
  이유를 알려준다. `127.0.0.1` 은 안전한 출처로 쳐서 그냥 되지만, 다른 기기에서
  `192.168.x.x` 로 접속하면 HTTPS 가 아니라 브라우저가 막는다.
- **가까운 역으로**는 찍어둔 핀을 가장 가까운 역에 맞춘다. 단축키는 출발지
  <kbd>D</kbd>, 도착지 <kbd>F</kbd> 다. 입력칸에 글을 쓰는 중에는 눌러도 듣지 않는다.
- **지원 역 표시**와 **지원 노선 표시**를 켜면 다룰 수 있는 역과 노선이 지도에
  겹쳐 보인다. 각각 옆의 삼각형을 누르면 도도부현별로 골라 볼 수 있다. 역 1,938개를
  하나씩 마커로 두면 버벅이므로 캔버스 한 장에 그린다.
- **경계선** 버튼(지도 오른쪽 아래)으로 보라색 권역선을 끄고 켠다.
- 출발지를 바꿔도 지도 축척은 그대로 둔다. 권역 전체를 다시 보려면 지도
  좌하단의 **권역에 맞추기**를 누른다.

## 성능

상한 60분 기준 등시선 0.6초, 경로 0.3초. 병목은 등고선 추출이라 상한을
180분으로 올리면 격자가 커져 2.4초가 된다.

계산할 필요가 없는 것은 잘라낸다. 소요 시간 상한보다 오래 걷는 것은 그렇게
역에 닿아도 이미 시간이 지나 권역에 못 들어오므로 탐색하지 않는다. 출발지
도보 원도 역에 닿을 수 있으면 60분으로 자른다. 전철이 훨씬 멀리 가므로 그
안에 묻혀 보이지 않는데, 상한만큼 그리면 반경 14 km 를 훑느라 1초를 쓴다.

## 가정

실제 소요시간에 영향을 주는 값들이다. 전부 `router.py` / `isochrone.py` 상단
상수로 뺐다.

| 항목 | 값 | 근거 |
|---|---|---|
| 도보 속도 | 분속 80 m | 일본 부동산 광고의 관행 기준. `router.WALK_SPEED` 한 곳에만 있다 |
| 우회 보정 | 직선거리 × 1.3 | 보행망 없이 돌 때만 쓰는 근사 |
| 계단 가중치 | 2.2배 | `highway=steps` 구간 |
| 보행망 격자 | 계산 40 m / 저장 100 m | 노드 477만 개, 간선 1,354만 개 |
| 구내 환승 | 3분 | 같은 역 구내 플랫폼 이동 |
| 개찰 밖 환승 | 5분 | 역명은 같지만 건물이 다른 경우 (예: 고탄다) |
| 승차 여유 | 1분 | 내려서 다시 타기까지 최소 시간 |
| 출발지 도보 | 최대 25분 | 집에서 역까지 |
| 하차 후 도보 | 최대 20분 (조절 가능) | 제한이 없으면 외곽 역 주변으로 권역이 과도하게 부푼다 |

### 보행망을 쓰면 얼마나 달라지나

기대만큼 극적이지는 않다. 신주쿠 09:00 출발 기준으로 도달 면적을 재보면:

| 출발지 | 상한 | 원 근사 | 보행망 | 차이 |
|---|---|---|---|---|
| 신주쿠 | 30분 | 146 ㎢ | 161 ㎢ | +11% |
| 신주쿠 | 60분 | 1,051 ㎢ | 1,108 ㎢ | +5% |
| 오다이바 | 30분 | 23 ㎢ | 22 ㎢ | -3% |
| 하치오지 | 30분 | 75 ㎢ | 84 ㎢ | +12% |

면적은 오히려 조금 늘기도 한다. 원 근사는 모든 방향에 1.3배 우회 penalty 를
일률적으로 매기는데, 실제 도로는 곧게 뻗은 방향으로는 1.0-1.1배밖에 안 되기
때문이다. 장벽 때문에 줄어드는 몫과 이 penalty 가 사라지는 몫이 상쇄된다.

달라지는 건 면적이 아니라 **모양**이다. 권역 경계가 도로를 따라 불규칙해지고,
수면·공항 부지·도로 없는 산지처럼 걸을 수 없는 곳이 깔끔하게 빠진다. 도쿄만
연안에서 차이가 가장 잘 보인다.

도쿄는 보행망이 워낙 촘촘하고 다리·건널목이 많아서 직선 근사가 우연히 잘
맞는 편이다. 하천이 넓고 교량이 드문 도시였다면 차이가 훨씬 컸을 것이다.

## 알려진 한계

- **철도만 다룬다.** 버스가 빠져 있어 역세권 밖 지역은 실제보다 도달권이
  좁게 나온다. 수도권 시내버스 GTFS는 ODPT 키가 있어야 받을 수 있다.
- **혼잡과 지연을 반영하지 않는다.** 시각표대로 움직인다고 본다.
- **횡단보도와 신호 대기를 세지 않는다.** 보행망은 도로 형상만 따르므로
  큰 교차로가 많은 구간은 실제보다 조금 빠르게 나온다.
- **건물 안 통로를 모른다.** 역 구내 환승은 고정값(3분 / 5분)으로 갈음한다.
- **자정을 넘는 운행**은 시각을 24시간 단위로 되감아 처리하지만, 출발 시각
  자체를 다음 날 새벽으로 주는 경우는 다루지 않는다.

## 구조

```
src/fetch_data.py    시각표 원본 수집
src/build_graph.py   직통 병합, 정차 이벤트 평탄화, 환승 간선 생성
src/router.py        RAPTOR 벡터화 구현 (도달시간 계산)
src/build_walk.py    OSM 보행망 추출 + 역별 도보권 + 원본 기하 + 육지 마스크
src/build_admin.py   OSM 행정경계에서 역마다 도도부현 붙이기
src/walknet.py       실행 중 보행망 조회 (역 도보권, 임의 지점 다익스트라)
src/finegeom.py      그린 도보선을 원본 도로 위로 다시 얹기
src/geometry.py      역 사이를 실제 선로 모양으로 (경로 표시, 노선 표시)
src/coverage.py      권역 범위 마스크와 경계선
src/region.py        권역 하나가 쓰는 것들을 한데 묶기
src/operators.py     철도 운영사 이름표 (검색 목록에서 동명 역 구분)
src/isochrone.py     격자 래스터화 + 등고선 → GeoJSON
src/server.py        Flask API
web/index.html       UI (구글 지도 / OpenStreetMap 양쪽 지원)
tests/               기준선 회귀 테스트 + 경계 회귀 테스트
```

## 도보 속도를 바꾸려면

`router.WALK_SPEED` 를 고친 뒤 `build_walk.py` 를 다시 돌려야 한다. 역별
도보권은 미리 계산해 저장해 둔 값이라, 상수만 고치면 실행 중 계산(출발지·
도착지)과 사전 계산(역 주변)이 서로 다른 속도로 돌게 된다.

### 데이터는 포함하지 않는다

시각표와 보행망은 저장소에 담지 않고 `fetch_data.py`, `build_walk.py` 로
각자 받는다. 코드만 올리고 데이터를 빼는 이유는 출처마다 재배포 조건이
다르고, 그중 일부를 확인할 수 없었기 때문이다.

| 출처 | 확인된 것 | 확인 못 한 것 |
|---|---|---|
| mini-tokyo-3d | 저장소 LICENSE 는 MIT. `data/` 에 별도 라이선스 파일이 없다 | README 는 데이터를 "ODPT 에서 받았다" 고만 적고, 재배포를 허락하는 문구가 없다 |
| ODPT | 데이터셋마다 라이선스가 다르다. CC BY 4.0, CC0, 공공교통 오픈데이터 기본 라이선스, 챌린지 한정 라이선스가 섞여 있다 | 우리가 쓰는 철도 시각표가 어느 쪽인지. 챌린지 한정 라이선스 전문은 계정이 있어야 볼 수 있다 |
| OpenStreetMap | ODbL. 파생 DB 를 배포하려면 같은 조건으로 공개하고 출처를 밝혀야 한다 | - |

mini-tokyo-3d 의 README 는 빌드에 ODPT Center 토큰과 Challenge 토큰을 둘 다
요구한다. 챌린지 한정 라이선스는 대개 기간과 용도를 묶어두므로, 시각표를
그대로 재배포하는 것은 조건을 확인하기 전에는 하지 않는 편이 안전하다.

데이터를 저장소에 같이 넣고 싶어지면 먼저 이것부터 할 것:

1. developer.odpt.org 에 가입해 우리가 쓰는 노선 데이터셋의 라이선스를 확인한다
2. 챌린지 한정 라이선스가 섞여 있으면 그 부분은 빼거나 ODPT 에 문의한다
3. OSM 파생물(보행망, 육지 마스크)을 넣는다면 ODbL 조건을 함께 명시한다

지금 구조에서는 이 셋 중 어느 것도 걸리지 않는다. 받는 코드만 올라가 있다.
